## 1. 研究与评测：MKA 多模态知识 Agent Benchmark

**发布时间：** 2026-11-10  
**发布方：** Google，与 Artificial Analysis 合作  
**官方来源：** [Google 官方介绍](https://blog.google/innovation-and-ai/models-and-research/gemini-models/multimodal-knowledge-agent-benchmark/)

### 它是什么？

MKA（Multimodal Knowledge Agent）是一个评测基准，用来测试 Agent 能不能处理真实工作中常见的复杂文件，而不只是回答纯文本问题。

例如：同时阅读 PDF、图表、图片、表格，理解它们之间的关系，再完成一份报告或演示文稿。

### 值得关注的设计

- 评测集包含 **200 个任务**，覆盖 10 个行业、83 类职业。
- 每个任务模拟多步骤专业工作，并配有专家编写的 Rubric；官方称每个任务约有 70 个是/否检查项。
- 评分约 75% 看事实准确性、25% 看视觉设计。
- Agent 评测器会打开文件、渲染页面、检查表格公式，并按专家 Rubric 检查交付物；Google 称专家与自动评测器的评分一致率为 96%。
- 200 个正式任务保持私有，同时公开了 10 个任务供外部测试。

### 为什么重要？

过去很多 Agent Benchmark 只看最终文字答案，容易忽略真实办公任务中的文件理解、格式、公式和视觉布局。MKA 把“能否交付可用成果”纳入评测。

### 对实际工作的启发

如果要评测一个办公 Agent 或自动化 Agent，可以借鉴它的设计：

1. 不只评估最终回答，还要检查产出的文件。
2. Rubric 拆成可验证的检查项，例如数据是否准确、公式是否正确、图表是否匹配、格式是否清晰。
3. 让不同模型使用相同工具、沙箱和任务预算，保证对比公平。
4. 保留私有测试集，避免模型通过搜索或训练数据提前见过答案。

**适合学习：** Agent 评测、Rubric 设计、多模态文件理解、办公自动化。

## 2. 前沿理论与安全：思维链可监控性（CoT Monitorability）

**发布时间：** 2026-11-10  
**发布方：** OpenAI Alignment Research  
**官方来源：** [What affects chain-of-thought monitorability across the model lifecycle?](https://alignment.openai.com/cot-monitorability-model-lifecycle/)

### 先用白话理解

思维链（Chain of Thought，CoT）可以粗略理解为模型在解决问题时呈现出来的推理过程。可监控性关注的是：我们能不能通过模型的推理过程或行为轨迹，发现它是否存在危险意图或不符合要求的行为。

### 研究讨论了什么？

OpenAI 研究了预训练、模型架构、强化学习（RL）以及使用模型生成数据进行微调（SFT），会怎样影响 CoT 可监控性。

文章重点讨论两个代理指标：

- **No-CoT capability：** 不显式输出思维链时，模型仍能完成推理任务的能力。
- **CoT controllability：** 模型按照指令改变或控制思维链表达的能力。

研究报告指出，随着模型能力提升，模型可能越来越不容易仅通过可见思维链来监控；强化学习和模型生成数据也可能影响思维链的可控程度。

### 需要注意的边界

这篇研究并没有证明“模型一定会隐藏恶意意图”。作者也明确指出，CoT controllability 是有噪声且不完美的代理指标，不能直接等同于模型成功逃避监控。

### 为什么重要？

模型越强，越不能只靠“看它怎么解释”来判断它是否安全。评测体系需要同时关注：

- 最终动作和工具调用轨迹；
- 模型在不同提示和对抗条件下的行为；
- 可见推理与实际行为之间是否一致；
- 多种独立指标，而不是依赖单一分数。

**适合学习：** AI 安全、Agent 行为评测、模型可监控性、评测指标设计。

## 3. 公司与产品：Databricks 新一代 Genie，走向持续运行的企业 Agent

**发布时间：** 2026-11-11  
**发布方：** Databricks  
**官方来源：** [Databricks 官方新闻稿](https://www.databricks.com/company/newsroom/press-releases/databricks-launches-new-always-genie-autonomous-ai-complex)

### 它是什么？

Databricks 宣布新一代 Genie，定位从“用户提问、AI 回答”进一步走向“用户给目标，Agent 持续推进任务”。

官方介绍的能力包括：

- 接收目标后持续跟进长期任务；
- 根据任务需要委派给多个子 Agent；
- 发现缺少信息时主动追问；
- 通过优先级收件箱和邮件提醒用户处理需要决策的事项；
- 通过 Genie Ontology 理解企业的数据定义、指标、人员和流程；
- 在企业现有权限、审批和审计规则下执行操作。

### 核心概念：Ontology（本体 / 业务语义层）

可以把它理解为企业的“业务说明书”：不仅告诉 AI 某个数据表叫什么，还告诉它指标代表什么、谁负责、流程如何运转、哪些人有权查看。

### 为什么重要？

企业 Agent 的难点不只是模型会不会推理，还包括它能不能理解企业上下文、访问正确的数据、遵守权限，并在长任务中持续跟进。

### 成熟度提醒

官方新闻稿称 Genie 和 Genie Ontology 已向客户普遍提供；新的 always-on Genie、Genie Search 和 Ontology Manager 则属于即将进入预览或 Beta 的能力。不要把所有新功能都理解为已经全面开放。

**适合学习：** 企业 Agent、RAG / 企业搜索、业务知识建模、权限治理、多 Agent 协作。

## 本期建议学习顺序

1. **先读 MKA Benchmark：** 学习如何把真实工作拆成评测任务和 Rubric。
2. **再读 CoT Monitorability：** 理解 Agent 安全评测为什么不能只看最终答案。
3. **研究 anthropics/skills：** 从一个官方 Skill 开始，观察它如何描述任务流程。
4. **最后看企业 Agent：** 对照 Genie 思考企业知识、权限和长期任务如何组合。
